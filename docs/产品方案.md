# PointLabStudio — 点云综合处理平台 · 产品方案 v0.1

> 基于 `vis_point_cloud.py` 演进；定位：**个人专业工具**（UI 好看、好用、专业）。
> 桌面原生应用 · Python + PySide6 + Open3D（算法/IO）· pygfx/wgpu（GPU 渲染）· 中文界面。

---

## 1. 需求回顾（已确认）

| 维度 | 决策 |
| --- | --- |
| 产品定位 | 个人专业工具，UI 必须好看 |
| 交付形态 | 桌面原生应用（类 CloudCompare） |
| 技术栈 | Python + PySide6 + Open3D |
| 渲染引擎 | pygfx（wgpu GPU 渲染），Open3D 仅做算法与 IO |
| 功能范围 | 滤波采样 / 配准对齐 / 分割聚类 / 测量 / 标注编辑 / 格式转换 / 大场景性能 / 批量流水线 |
| 脚本化 | 是，**命令内核**作为核心架构能力 |
| 数据规模 | 不固定（单帧 → 亿级），**系统自动判断并适配**，同一窗口展示 |
| 数据来源 | KITTI/nuScenes 等雷达 .bin 序列 + pcd/ply 等通用格式 |
| 开发节奏 | 单人业余时间，每阶段必须有可交付成果 |
| 界面语言 | 中文为主，架构预留 i18n |

**一句话愿景**：一个现代化的桌面点云工作站——打开即用、处理成链、结果可复现。

---

## 2. 设计原则（后续所有功能的标尺）

1. **一切皆可浏览**：任何操作的结果立即在视口中可视化。
2. **命令化内核**：每个功能 = 一个 Command（参数校验 + 执行 + 撤销），UI 只是命令的调用者。批处理、脚本、历史回放全部复用同一内核 → 功能复利。
3. **非破坏性编辑**：源数据只读，处理产生派生实体，随时回退。
4. **规模自动适配**：用户无需关心点云大小——同一窗口、同一套交互，系统自动分级加载与渲染，任何规模交互 ≥ 60fps。
5. **好看**：Apple/Google 式设计语言——克制的配色、精致的字体与间距、统一深色主题（浅色可选）。

## 3. 功能全景

标记：⭐ = MVP（Phase 1）；◆ = 核心（Phase 2–4）；◇ = 进阶（Phase 5+）

### 3.1 数据管理（⭐）
- 工程树（DB Tree）：多片点云、分组/文件夹、可见性开关、重命名、拖拽排序
- 属性面板：点数、包围盒、密度、内存占用、标量场列表、直方图
- 工程文件 `.pls`：保存工程结构、视角、显示状态、处理参数；源数据以路径引用
- 最近文件、拖放打开、目录批量导入

### 3.2 统一自动适配加载（Auto-Ingest，⭐）

**核心承诺：无论是 50 万点的单帧还是 5 亿点的大场景，都是同一个窗口、同一套操作，系统自动判断并展示，不存在"大点云窗口 / 普通点云窗口"之分。**

- **输入**：拖放单文件或文件夹（含子目录，自然排序），自动收集（沿用现有 `collect_files`）
- **格式识别**：扩展名 + 内容嗅探；`.bin` 维度沿用现有启发式评分，不确定时弹一次确认框（可批量套用）
- **规模探测**：文件大小 + 头部/首块读取 → 预估点数与内存，自动分级：S（< 100 万）/ M（100 万–1 亿）/ L（≥ 1 亿）
- **先粗后精（秒开）**：大文件打开立即显示低分辨率预览，后台流式加载精细数据逐步替换，进度显示在状态栏与实体节点
- **全程透明**：无任何"模式"概念；属性面板仅展示当前加载比例/渲染精度，可选"强制全量加载"
- **翻页切换**：沿用现有 ←/→ 切换习惯，任意规模切换同样无感

### 3.3 3D 可视化（⭐）
- 单主视口 + 可选正交三视图 / 2D 截面视图（◆）
- GPU 点渲染：点大小（屏幕空间/世界空间）、圆点/方块、透明度
- 背景色/渐变、坐标轴、地面网格、雾
- 标量场伪彩色：色彩映射表（turbo/viridis/高度梯度/强度等）、颜色条图例、范围调节
- 点选/框选/套索选择；裁剪盒（Clipping Box）⭐ / 任意裁剪平面 ◆
- 相机：透视/正交、预设视角、飞行到选中对象
- 大场景：八叉树 LOD + 视锥剔除 + 分块流式加载——由 Auto-Ingest 自动调度，用户零干预（⭐ 骨架，◆ 完善）

### 3.4 处理算法（◆）
- **滤波与采样**：体素降采样、随机采样、统计离群点去除（SOR）、半径离群点去除（ROR）、盒/面裁切
- **配准**：ICP（点到点/点到面）、全局粗配准（FGR/RANSAC）、手动三点对齐、刚体变换编辑器（平移/旋转/缩放 + 矩阵导出）
- **分割**：平面分割（RANSAC）、地面提取、欧式聚类（DBSCAN）、区域生长、连通分量
- **分析**：法线估计、曲率、密度、Cloud-to-Cloud 距离
- **网格化**（◇ 可选）：Poisson / Alpha-shape / Ball pivoting

### 3.5 测量与标注（◆）
- 点选测距、折线累计测距、角度、面积、坐标拾取，结果导出 CSV
- 截面分析：任意平面切 2D 剖面视图，剖面点云可导出
- 标注：框选/套索/画笔选择、删除点、打标签（labels 标量场）、分割结果拆分/合并/上色

### 3.6 IO 与格式（⭐ 基础，◇ 扩展）
- 导入：现有 bin/pcd/ply/xyz/pts/npy/npz/txt/csv + las/laz、e57（◇）
- `.bin` 维度自动识别：保留现有启发式 + **可视化确认对话框**（识别结果/评分可人工纠正）
- 导出：pcd/ply/las/txt 等，支持子集导出（选中点/当前分割）
- 大文件分块读取（bin/pcd），mmap 懒加载

### 3.7 批处理与脚本（◇）
- 处理链编辑器：把操作编排成流水线（节点图），一键执行、中间结果预览、参数复用
- Python 脚本控制台：内嵌控制台直接调用 core API，脚本可保存复用
- headless CLI：无界面批量执行（继承现有 `vis_point_cloud.py` 的 CLI 体验）

## 4. 技术架构

### 4.1 选型总览

| 层 | 选型 | 理由 |
| --- | --- | --- |
| UI | PySide6（QWidgets + QSS 设计系统） | 生态成熟、Dock 布局强大，可按 Apple/Google 设计规范完全自定义外观 |
| 3D 渲染 | pygfx（wgpu 后端） | 现代 GPU 渲染、与 Qt 无缝嵌入、亿级点可行、着色器可控（裁剪盒/EDL） |
| IO + 算法 | Open3D | 复用现有读取代码与成熟算法；**不初始化其 GUI 模块**，避免与渲染层冲突 |
| 数值 | numpy / scipy | 基础计算、直方图、KDTree 等 |
| LAS/LAZ | pylas / laspy（◇） | 测绘格式支持 |
| 打包 | PyInstaller（◇） | 单 exe 分发 |

### 4.2 分层架构与目录

```
PointLabStudio/
├── apps/                      # 入口：desktop 主程序、CLI（headless）
├── ui/                        # PySide6 界面层（依赖 core，不反向）
│   ├── main_window.py         # 主窗口、菜单、Dock 布局
│   ├── theme/                 # QSS 主题、图标、调色板
│   ├── widgets/               # 工程树、属性面板、直方图、颜色条、日志面板
│   ├── viewport/              # pygfx 视口：场景、相机控制、拾取、裁剪盒、LOD
│   └── tools/                 # 交互工具：测量、选择、标注、三点配准
├── core/                      # 领域核心（纯 Python，无 UI 依赖）
│   ├── model/                 # Project / CloudEntity / ScalarField
│   ├── commands/              # Command、History（Undo/Redo）、参数 schema
│   ├── algorithms/            # 滤波/配准/分割/分析（包装 open3d/numpy）
│   ├── io/                    # 格式读写（迁移现有 load_*）、.bin 识别、分块读取
│   ├── color/                 # 色彩映射表系统（迁移 scalar_to_rgb）
│   ├── pipeline/              # 处理链、脚本 API
│   └── render/                # 渲染适配接口 IRenderer（pygfx 实现 + 回退实现）
├── resources/                 # 图标、色彩映射表定义
└── tests/                     # 单元测试（core 优先，算法与 IO 全覆盖）
```

**依赖方向**：`ui → core`，`core` 不依赖任何 UI 库；`render` 层定义抽象接口，视口实现可替换（pygfx 主实现、Open3D 降级实现），这是渲染风险的对冲手段。

### 4.3 数据模型（核心设计）

- **Project**：工程 = `.pls` 文件（JSON），包含实体树、视图状态、显示配置、处理历史。
- **CloudEntity**（现有 `CloudData` 的升级）：
  - `geometry`：xyz 固定属性 + **标量场集合**（intensity、rgb、labels、自定义标量），大文件为分块数组（mmap 懒加载）
  - `transform`：4×4 变换矩阵（支持多片点云全局变换）
  - `display`：可见性、点大小、颜色模式（标量场名 + 色彩映射 + 值域）、透明度
  - 缓存：包围盒、法线、八叉树
- **ScalarField**：命名标量场，含统计量（min/max/直方图）与默认色彩映射；每片点云可有任意多个标量场。
- **Command**：`run(inputs, params) → outputs`，支持撤销（快照/逆操作二选一）与 JSON 参数序列化——这是批处理与脚本的基石。

### 4.4 线程与性能模型

- 主线程：UI + 渲染，永不阻塞（IO/算法一律后台）。
- 后台：QThreadPool 执行加载与算法；任务面板显示进度、支持取消；日志面板复用现有 verbose/debug 输出习惯。
- **自动分级引擎（Auto-Ingest）**：加载时自动探测规模并选择策略，对用户完全透明：
  - S（< 100 万点）：全量内存 + GPU 直渲，无额外机制
  - M（100 万 ~ 1 亿）：分块 mmap + GPU 渲染 + 视锥剔除
  - L（> 1 亿）：分块 mmap + tile 缓存（LRU）+ 八叉树 LOD + 按视锥请求块
- **首屏预览**：大文件先渲染低分辨率采样，后台流式升级为全量，保证"秒开"体验。
- 基准要求：Phase 1 即用 1 亿点文件做加载与交互帧率基准，性能回归在每阶段末尾检查。

### 4.5 渲染方案要点

- pygfx `Points` + wgpu 后端，嵌入 Qt（wgpu-py 的 Qt Canvas）
- 色彩映射走纹理采样，支持任意断点、对数/百分位归一（迁移 `robust_norm` 的 2–98 百分位思路）
- 裁剪盒：shader clip plane，GPU 侧裁剪
- 拾取：pygfx 内置 GPU picking（点选）+ CPU 八叉树求交（框选/套索）
- 交互习惯保留：R 重置视角、C 循环颜色、+/- 点大小、WASD/QE 平移——移植现有回调逻辑到新视口控制器

### 4.6 现有代码资产复用映射

| 现有代码 | 去向 | 说明 |
| --- | --- | --- |
| `collect_files` / 自然排序 | `core/io/scanner.py` | 保留，加拖放/多选 |
| `infer_bin_dim` / `score_bin_dim` / `path_dim_hint` | `core/io/bin_reader.py` | 保留启发式 + 新增确认对话框 |
| `robust_norm` / `scalar_to_rgb` / `array_to_rgb` | `core/color/` | 升级为色彩映射表体系 |
| `load_bin` / `load_npy_npz` / `load_ascii` / `load_open3d_cloud` | `core/io/readers.py` | 输出从 `CloudData` 升级为 `CloudEntity` |
| `sanitize_cloud` / `sample_cloud` | `core/geometry/ops.py` | 保留 |
| `CloudData` | `core/model/CloudEntity` | 数据结构升级 |
| 键盘回调 / 相机平移 | `ui/viewport/controller.py` | 交互习惯完整保留 |

## 5. UI/UX 设计（Apple / Google 设计语言）

> **v0.1 实现说明**：本版本按「原创 Studio 布局」实现，刻意避免 CloudCompare 的
> 「左侧 DB Tree + 顶部工具栏 + 右侧属性面板」结构。实际布局为：自绘顶栏（品牌＋打开/工程/主题/帮助）
> ＋ 左侧「场景」卡片列表 ＋ 中央视口（底部悬浮胶囊工具条）＋ 右侧「检查器」分节面板 ＋ 底部状态栏
> ＋ 可收起日志抽屉。本节的配色/字体/圆角/间距规范作为设计基线沿用。

整体风格参考 Apple 的克制与层级感 + Google 的清晰信息密度，目标关键词：**干净、克制、精致、专业**。

### 5.1 字体
- 界面字体：**Inter**（Google 系开源字体，风格接近 SF Pro）；中文回退微软雅黑 / PingFang SC
- 数据/坐标/日志：等宽字体 **JetBrains Mono**（或 Cascadia Code）
- 字号体系：11 / 12 / 13 / 15 / 17 / 22 / 32（面板小字 11–13，正文 13–15，标题 17–22，空态大标题 32）
- 大标题紧凑字距（-0.3px），数字用 tabular-nums 对齐
- 说明：SF Pro 受 Apple 授权限制不可随应用分发，故用 Inter 替代

### 5.2 配色（Design Tokens）
- **深色主题（默认）**：背景 #0D0D0F，一级面板 #1C1C1E，二级面板 #2C2C2E，分隔线 rgba(255,255,255,0.08)
  - 主文字 #F5F5F7 / 次文字 #98989D；强调色 #0A84FF；成功 #30D158 / 警告 #FF9F0A / 危险 #FF453A
- **浅色主题**：背景 #F5F5F7，面板 #FFFFFF，次级面板 #F2F2F7，分隔线 rgba(0,0,0,0.08)
  - 主文字 #1D1D1F / 次文字 #6E6E73；强调色 #007AFF；成功 #34C759 / 警告 #FF9500 / 危险 #FF3B30
- 强调色仅用于：选中态、主按钮、焦点、当前工具；大面积界面保持中性灰
- 视口背景：深色渐变（径向微光，类 Apple 3D 展示风格）；数据伪彩色（turbo/viridis 等）不随主题变化

### 5.3 形状、间距与层次
- 圆角：控件 6px、输入框/卡片 8px、面板卡片 12px、对话框 16px
- 间距：4px 网格（4 / 8 / 12 / 16 / 24 / 32）
- 层次：优先用"细描边 + 轻阴影"分层（深色主题以 1px 描边为主），避免重阴影与高饱和色块
- 图标：单色线条图标、1.5px 笔画、圆角风格（Lucide），禁用态 40% 透明度

### 5.4 布局
- 中央 3D 视口；左侧工程树（DB Tree）+ 属性面板；右侧工具面板；底部状态栏（点数/帧率/内存/坐标系）+ 日志；全部 Dock 可折叠拖拽
- 顶部工具栏：打开/保存/撤销重做/视图/测量/分割等高频操作；低频操作在菜单与右键上下文菜单
- 空状态（无数据时）：居中大标题 + 引导按钮（"拖入点云文件或文件夹"），类 Apple 空态设计

### 5.5 动效
- 150–250ms ease-out，仅用于：面板折叠、工具切换、按钮 hover/按下、加载进度
- 3D 视口内不做装饰动画，保证渲染专注与流畅

### 5.6 快捷键与上下文
- 完整继承现有习惯（R/H/C/+/-/WASD/QE），新增 Ctrl+Z/Y、Delete 删除选中、Ctrl+拖拽选择等
- 工程树节点与视口内右键菜单：设为颜色、导出、隐藏、聚焦、强制全量加载等

## 7. 关键风险与对策

| 风险 | 等级 | 对策 |
| --- | --- | --- |
| pygfx 生态较新、集成细节未知 | 高 | P0 先行验证；`core/render` 抽象接口，兜底降级到 Open3D 视口 |

| 单人体力 vs 功能野心 | 中 | 命令内核让功能复利增长；明确不做网格编辑/纹理映射等重功能；严格按里程碑裁剪 |
| wgpu 驱动兼容性（集显/老驱动） | 中 | P0 验证；提供 CPU 回退路径（低点数降级渲染） |

## 17. 交互修复（v0.6.1）

**框选/测量时相机仍在旋转（关键缺陷）**
- 根因：`renderer.remove_event_handler(self.controller)` 未指定事件类型，pygfx 只会移除
  指定类型的回调，实际什么都没移除；控制器继续响应拖拽，于是"一拖就转视角"，框选/拾取随之失效
- 修复：改用官方 `controller.enabled` 开关，进入测量/选择时 `enabled=False`，退出恢复
- 实测：选择模式拖拽相机位移 **0.000000**、框选 72,280 点；测量模式相机位移 0、距离正常
- 体验补充：模式下保留滚轮缩放（手动实现），不至于完全不能调整视角

**裁剪后撤销无效**
- 根因：裁剪范围只是显示裁剪（视口掩码），从未写入历史，Ctrl+Z 自然不会恢复
- 修复：裁剪状态纳入历史
  - `B` 键/顶栏切换：立即记一条「裁剪范围」
  - 弹层面板修改：350ms 防抖后提交一条，避免拖动数值时刷屏
  - 撤销/重做恢复「启用状态 + 六向范围」，且不会重复入栈
- 数据级裁剪仍走「处理 → 盒裁切」（生成新点云，独立可撤销）

**验证**：审计 **48/48**（新增"裁剪可撤销/重做""裁剪弹层修改可撤销""选择/测量时相机冻结"三项）、
单元测试 28 项、冒烟测试 10 项通过。
